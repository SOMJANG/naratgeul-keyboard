# 나랏글 키보드

아이폰용 나랏글(천지인 아님) 한글 키보드 확장. 개인 사용 목적으로 직접 빌드해서 쓴다.

- 최소 지원: iOS 16.0 / 확인 목표: **iOS 26, 27**
- 네트워크 코드가 없다. 입력 내용은 기기 밖으로 나가지 않는다
- 전체 접근 권한(Full Access)은 키 눌림 진동에만 쓴다. 안 켜도 입력은 전부 된다

## 구조

```
NaratgeulKeyboard.xcodeproj
Shared/                         앱과 확장이 같이 쓰는 순수 로직 (UIKit 의존 없음)
  Hangul.swift                  한글 유니코드 조합/분해
  NaratgeulEngine.swift         나랏글 오토마타
  KeySequence.swift             글자 → 키 순서 되짚기 (연습 힌트용)
NaratgeulKeyboard/              컨테이너 앱 (설치 안내 + 연습 모드 + 시험 입력창)
  PracticeItems.swift           연습 문제 (7단계 47문제)
  PracticeView.swift            연습 화면
  AppIcon.icon/                 Liquid Glass 앱 아이콘 (변란 + '나' 두 겹)
NaratgeulKeyboardExtension/     키보드 확장 본체
  KeyboardViewController.swift  UITextDocumentProxy 연결
  KeyboardRootView.swift        SwiftUI 레이아웃
  KeyButton.swift  KeyModels.swift  KeyboardTheme.swift
Tests/                          오토마타 테스트 (Xcode 없이 실행 가능)
```

## 연습 모드

컨테이너 앱에서 자음 자리 → 획 → 쌍 → 모음 → 받침 → 낱말 → 문장 순으로 익힌다.
문제마다 "누르는 순서 보기"를 펴면 어떤 키를 어떤 차례로 누르는지 나온다.
이 순서는 `KeySequence` 가 오토마타 규칙을 거꾸로 훑어 만든다.

## 입력 규칙

자음 키는 ㄱ ㄴ ㄹ ㅁ ㅅ ㅇ 여섯 개, 모음 키는 ㅏㅓ ㅗㅜ ㅣ ㅡ 네 개뿐이다.
나머지는 **획**과 **쌍** 키로 만든다.

```
획 추가   ㄱ↔ㅋ   ㄴ→ㄷ→ㅌ→ㄴ   ㅁ→ㅂ→ㅍ→ㅁ   ㅅ→ㅈ→ㅊ→ㅅ   ㅇ↔ㅎ
쌍자음    ㄱ↔ㄲ   ㄷ↔ㄸ   ㅂ↔ㅃ   ㅅ↔ㅆ   ㅈ↔ㅉ
모음      ㅏㅓ 키 두 번 → ㅏ↔ㅓ      ㅗㅜ 키 두 번 → ㅗ↔ㅜ
ㅑㅕㅛㅠ   ㅏㅓㅗㅜ 입력 후 획 키
ㅐㅔ       ㅏㅓ 뒤에 ㅣ
ㅘㅝ       ㅗㅜ 뒤에 ㅏㅓ 키
```

예: `안녕` = ㅇ, ㅏㅓ, ㄴ, ㄴ, ㅏㅓ, ㅏㅓ, 획, ㅇ

획과 쌍은 **방금 낸 자음**을 대상으로 삼는다. 받침 자리에서도 마찬가지다.

```
겹받침에 획   ㄻ → ㄼ → ㄿ → ㄻ   (뒤쪽 ㅁ→ㅂ→ㅍ 만 바뀐다)
```

`넓` 은 ㄹ 뒤에 ㅁ 을 누르는 순간 ㄻ 으로 붙어 버려서, 획이 겹받침에 먹지 않으면
칠 방법이 아예 없다. `읊` 도 같다.

된소리가 받침으로 설 수 없으면 (`ㄸ ㅃ ㅉ`, 또는 `ㄹ+ㅆ` 같은 조합) 그 자음은
다음 글자의 초성으로 내려간다. `이따` 는 `인` 에서 쌍을 눌러, `날씨` 는 `낤` 에서
쌍을 눌러 이 길로 간다.

## 레이어

한글 · 영문 · 숫자 · 기호 · 이모지 다섯 벌이다. 위쪽 탭바로 직접 고르거나,
모든 레이어의 오른쪽 아래 같은 자리에 있는 **지구본 키**로 돌린다.

```
한글 →(1번) 영문 →(2번) 이모지 →(3번) 한글
```

지구본 키를 시간 창(더블탭)이 아니라 순환으로 만든 이유는, 한 번 누른 순간
레이어가 바뀌면서 그 자리의 키도 같이 바뀌면 두 번째 탭이 갈 곳이 없어지기 때문이다.
자리를 고정하고 순환시키면 타이밍과 무관하게 "한 번 영문, 두 번 이모지"가 성립한다.

이모지는 시스템 이모지 키보드로 넘어가는 공개 API가 없어서 자주 쓰는 200개를
직접 담아 그린다.

### 숫자와 기호

숫자·기호도 한글과 같은 **4×4 격자**다. 원래 나랏글 배열을 그대로 따랐다.

```
1        2   3    ⌫        (-)      ₩$¥  ^%#  ⌫
4        5   6    ↵        {*}      +×÷  <=>  ↵
7        8   9    .,?!     [:]      "';  /\|  .,?!
#+= 한글  0   간격  🌐       123 한글  ~…•  간격  🌐
```

한글 레이어(⌫ · 간격 · ↵)와 달리 **간격이 오른쪽 열에 없다.** 격자 안쪽
마지막 행 셋째 칸으로 내려가고, 그 자리를 `.,?!` 가 받는다. 마지막 행 왼쪽
칸은 전환 키(`#+=` / `123`)와 `한글` 키가 반씩 나눠 쓴다.

레이어마다 오른쪽 열이 어긋나는 게 좋아 보이지는 않지만, 이미 손에 익은
배열을 바꾸면 그쪽이 훨씬 큰 오타 요인이라 원본을 따랐다.

기호는 한 키에 서너 개씩 묶여 있고, **같은 키를 다시 누르면 다음 기호로 바뀐다.**
ㅏㅓ · ㅗㅜ 키를 두 번 눌러 뒤 글자로 넘기는 것과 같은 방식이다.
라벨에 적힌 순서 그대로 돌고, 다른 키가 한 번이라도 끼어들면 거기서 확정된다.

```
₩$¥ 한 번 → ₩      두 번 → $      세 번 → ¥      네 번 → ₩
```

바꿔 끼울 때 커서 앞 글자가 방금 넣은 그 기호인지 먼저 확인한다.
사용자가 화면을 탭해 커서를 옮긴 뒤 같은 키를 또 누르면
엉뚱한 글자를 지우게 되기 때문이다.

## 빌드해서 설치하기

Xcode가 필요하다 (App Store에서 설치). 무료 Apple ID로도 된다.

```bash
git clone git@github.com:SOMJANG/naratgeul-keyboard.git
```

1. `NaratgeulKeyboard.xcodeproj` 를 Xcode로 연다
2. 프로젝트 설정 → `Naratgeul` 과 `NaratgeulKeyboardExtension` 두 타깃 모두
   **Signing & Capabilities** 에서 본인 Apple ID 팀을 고른다
3. 번들 ID가 이미 쓰이고 있다는 오류가 나면 두 타깃 모두 접두사를 바꾼다
   (확장 ID는 반드시 앱 ID 뒤에 `.Keyboard` 가 붙은 형태여야 한다)
   `project.pbxproj` 에는 내 팀 ID와 `com.somjang.*` 번들 ID가 그대로 들어 있으니
   클론해서 쓴다면 2·3번은 반드시 본인 것으로 바꿔야 한다
4. 아이폰을 케이블로 연결하고 실행 대상으로 고른 뒤 ⌘R
5. 아이폰에서 **설정 → 일반 → VPN 및 기기 관리** → 본인 개발자 앱 신뢰
6. **설정 → 앱 → 나랏글 → 키보드** 에서 나랏글 스위치를 켠다
7. 키를 누를 때 진동이 오게 하려면 같은 화면에서 **전체 접근 허용** 도 켠다 (선택)

서드파티 키보드는 전체 접근 권한 없이는 햅틱 API를 불러도 아무 일도 일어나지 않는다.
애플이 막아 둔 부분이라 우회로가 없어서, 진동을 원하면 권한을 켜는 수밖에 없다.
클릭 **소리**는 권한과 무관하게 난다.

iOS 26부터 타사 키보드를 켜는 자리가 `일반 → 키보드` 아래에서 앱별 설정으로 옮겨졌다.
지구본 키를 눌렀을 때 나랏글이 먼저 뜨게 하려면
**설정 → 일반 → 키보드 → 키보드 → 편집** 에서 맨 위로 올린다.

무료 Apple ID로 서명하면 인증서가 **7일**마다 만료된다. 만료되면 Xcode에서 ⌘R로
다시 설치하면 된다. 유료 개발자 계정(연 $99)이면 1년이다.

Xcode 없이 Swift 커맨드라인 툴만 있으면 오토마타를 검증할 수 있다.

```bash
./Tests/run.sh
```

기호 묶음 키, 문장)를 확인한다.

여기에 더해 `KeySequence` 가 내놓은 키 순서를 다시 오토마타에 넣어 원래 글자가
나오는지 되짚는다. 연습 문제 47개와 **한글 음절 11,172자 전부**를 훑는다.
표를 손으로 뒤집어 놓은 것이라 조용히 어긋나기 쉬운데, 이 전수 검사가 그걸 막는다.
`ㄼ`·`ㄿ` 받침을 칠 수 없던 것도 이 검사에서 드러났다.

## iOS 26 이후를 위해 신경 쓴 것

기존 서드파티 키보드에서 자주 터지던 지점들을 미리 막아 뒀다.

- **키보드 높이** — `inputView.allowsSelfSizing` 을 켜고 높이 제약의 우선순위를
  `.required - 1` 로 둔다. 시스템 제약과 충돌해서 앱이 죽는 흔한 원인을 피한다.
- **아래쪽 잘림** — `UIHostingController.safeAreaRegions = []`. 시스템이 이미 홈
  인디케이터 여백을 붙이는데 SwiftUI가 한 번 더 붙이면 마지막 행이 잘린다.
- **가로 모드** — 키 높이를 고정하지 않고 늘어나게 두고, 세로 크기 등급이 compact이면
  전체 높이를 줄인다. 가로로 눕혔을 때 키보드가 화면을 다 덮지 않는다.
- **커서 이동 후 오입력** — iOS에는 조합 중 글자를 표시하는 preedit API가 없어서
  글자를 직접 넣었다 지우는 방식을 쓴다. 사용자가 화면을 탭해 커서를 옮기면 그 글자가
  더 이상 커서 앞에 없는데, 그대로 두면 다음 입력 때 엉뚱한 글자를 지운다.
  키를 처리하기 전에 문서 내용과 조합 상태가 맞는지 매번 확인한다.
- **보안 입력 필드** — 비밀번호 칸에서는 커서 앞 문맥을 읽을 수 없다.
  이 경우 문맥에 기대는 동작을 건너뛰고 조합 상태만으로 처리한다.
- **위쪽 이음매** — 입력 뷰에 불투명한 배경을 칠하지 않는다. iOS 26은 키보드를
  모서리가 둥근 반투명 판 위에 얹어 주는데, 여기에 각진 불투명 배경을 깔면
  색과 모서리가 어긋나 위쪽에 띠가 보인다. 시스템 배경이 그대로 비치게 둔다.
- **등장 직후 높이 튐** — `viewWillAppear` 에서 높이를 다시 계산한다.
  `viewDidLoad` 시점의 `traitCollection` 은 아직 확정 전이라 값이 틀릴 수 있다.

## 반응 속도

키 하나 누르는 데 드는 비용을 줄여 뒀다. 굼뜬 느낌의 원인은 대개 두 군데다.

- **호스트 앱과의 왕복** — `documentContextBeforeInput` 은 다른 프로세스에서 가져오는
  값이라 입력 경로에서 제일 비싸다. 예전엔 키 하나에 상태 확인용 한 번, 엔진에 넘기려고
  한 번, 거기에 우리가 넣고 지운 글자 때문에 되불린 `textDidChange` 에서 또 한 번 읽었다.
  지금은 키당 한 번만 읽어 돌려 쓰고, `textDidChange` 는 우리 편집이면 건너뛴다.
  레이어 전환처럼 문서를 안 건드리는 키는 아예 읽지 않는다.
- **오프스크린 렌더 패스** — 눌림 표시에 `.brightness()`, 키 그림자에 `.shadow()` 를
  쓰면 키마다 별도 렌더 패스가 생긴다. 눌린 색은 미리 계산해 두고 채우기만 갈아 끼우고,
  그림자는 같은 모양을 1pt 내려 까는 걸로 바꿨다. 보이는 결과는 같다.
- **제스처 인식 경쟁** — 키 터치를 SwiftUI 제스처가 아니라 UIKit 의 `touchesBegan`
  으로 직접 받는다 (`KeyTouchArea`). `DragGesture(minimumDistance: 0)` 도 누르는 즉시
  불리긴 하지만 제스처인 이상 상위 인식기들과 경쟁을 거치고, 키보드에선 그 한 박자가
  그대로 느껴진다. 키마다 자기 터치를 따로 받아서 두 키를 겹쳐 눌러도 서로 먹히지 않는다.

피드백(소리·진동)은 문서 작업보다 **먼저** 낸다. 뒤에 두면 왕복이 끝난 뒤에야 울려서
느리게 느껴진다.

## 확인한 것

시뮬레이터(iPhone 17 / iOS 26.5)에서 빌드·설치해 동작을 확인했다.
Safari 주소창처럼 앱 밖에서 올라오는 경우도 포함한다.
실기기(iPhone 15 Pro / iOS 26)에는 무료 Apple ID 서명으로 설치해 실제로 쓰고 있다.

키보드가 **처음** 올라올 때 1초 남짓 빈 판이 보였다가 채워지는데, 이건 확장이
별도 프로세스로 처음 실행되는 지연이다. 한 번 뜬 뒤로는 30프레임 연속 측정에서
높이가 고정이었다.

## 알려진 제한

- 오른쪽 기능 열의 폭(`KeyboardTheme.functionColumnRatio` ·
  `keypadFunctionColumnRatio`)은 원본 화면을 눈으로 재서 잡은 값이다.
- 같은 기호 키에 묶인 기호 둘을 잇달아 칠 수 없다. `?!` 를 치면 `!` 가 `?` 를
  덮어쓴다. 사이에 다른 키가 끼면 정상이다.
- 커서 이동 제스처(스페이스바 쓸기)는 없다.
- 이모지는 목록이 고정이고 최근 사용·검색·스킨톤 선택이 없다.
